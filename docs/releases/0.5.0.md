# T2K 0.5: executable graph reasoning and candidate authoring

The coordinated stable release is `@t2kai/core@0.5.0`,
`create-t2k@0.5.0`, and `@t2kai/mcp@0.4.0`, under npm's `latest` tag.
It promotes the 0.5.0-rc.1 Core/create-t2k and 0.4.0-rc.1 MCP candidates after
registry and Studio acceptance. Graph reasoning remains an explicitly
experimental API within these stable packages; publication and acceptance
receipts establish which release stage has completed.

```bash
npm install @t2kai/core@0.5.0
npx create-t2k@0.5.0 my-decision-loop
npx -y @t2kai/mcp@0.4.0 --help
```

## What changes

`@t2kai/core/reasoning` now ships in the npm package. It compiles typed JSON
programs against an accepted ontology and executes them against one authorized,
time-pinned graph snapshot. The fixed operations are lookup, traversal,
conjunctive filters, projection and numeric aggregation. Results preserve claim
revisions, considered and supporting evidence, exclusions, row derivations,
issues, traces and deterministic hashes. Incomplete, stale or conflicting inputs
remain `needs_review`; computation never authorizes a downstream action.

Provider-neutral generation proposes and repairs programs using development
cases within explicit attempt and request budgets. The host supplies the model
adapter and owns credentials, call limits and durable checkpoints. A separate
trusted harness preflights and freezes final evaluation, computes status/value
and evidence checks, and retains an acceptance report. Final tests must stay
outside candidate search. See the [API and complete limits](../GRAPH_FUNCTIONS.md).

Published Core tarballs include `package.json.t2kReasoningBuild`, a digest
manifest for executable build identity. It supports hosts that bind evaluation
and activation to verified installed bytes. npm provenance separately establishes
publication origin. Neither a digest nor a finite passing test suite proves
source authenticity, real-world correctness or permission to act.

Both scaffolder profiles pin the coordinated Core version. MCP consumes that
Core build and retains its existing safe tools and human-governance boundaries;
this release does not add graph-function activation through MCP.

## Compatibility and preview migration

The normative ontology-pack schema, policy replay and promotion rules, database
layout and existing public integration APIs are unchanged. Graph reasoning
remains explicitly experimental through stable package promotion. There is no
implicit units conversion, arbitrary code, grouping, distinct, ranked output,
arithmetic expression language, disjunction or function-call composition.

`t2k.graph-function.v1` remains the program artifact version. Private-preview
`t2k.graph-evaluation.v1` suites are rejected. Review each old evidence assertion
and assign it to supporting, considered, exclusion or per-row evidence in a
`t2k.graph-evaluation.v2` suite. Freeze its new hash and rerun evaluation; there
is no silent reinterpretation of `requiredClaimIds` or old acceptance reports.

A Studio or other host migrating from a private preview must verify the installed
package identity, recompile the preserved program, and revalidate acceptance
against the new execution binding before activation. Historical receipts remain
bound to their original build. The migration itself does not need a new model
call or changes to observed facts.

## Release verification

The [release procedure](../RELEASING.md) requires clean Core tests, PostgreSQL 16
lifecycle checks, conformance examples, generated-project tests, exact packed
Core/MCP dependency resolution, installed-byte identity checks and Studio
compatibility. Signed annotated tags must point to protected-main commits, and
GitHub must verify their signatures. Prereleases publish explicitly to `next`;
new stable-version artifacts publish explicitly to `latest`, through OIDC with
npm provenance.

# T2K 0.4.2: Fail-Closed Inputs and Bound Review Evidence

T2K 0.4.2 is a patch release that closes malformed-input gaps, binds lifecycle
and browser-review decisions to the evidence they evaluated, and hardens the
local integration-hub demonstration without changing its non-activating scope.

## Fail-closed runtime boundaries

- Purpose-limited access accepts only the documented rule keys. A typo or
  undeclared property makes the request invalid instead of being ignored.
- Reference policy and Postgres path lookups traverse only own properties and
  own array indexes. Prototype-inherited values cannot satisfy a policy path.
- Source execution applies schema-aligned validation to executable mapping
  metadata, identities, and field mappings. Malformed identities, blank metadata, unsafe or
  non-namespaced targets, repeated normalization steps, and invalid field
  definitions cannot produce a mapped, no-review result.
- Entity-resolution rule identifiers must be unique. Repeating an identifier is
  invalid input and cannot amplify the same evidence toward an automatic link.

These are patch-compatible changes for well-formed 0.4 inputs. Callers that
relied on ignored misspellings, inherited properties, malformed executable
mappings, or duplicate rule IDs now receive the intended fail-closed result.

## Lifecycle evidence binding

A persisted reward assessment records a deterministic hash of the observation
IDs it evaluated. Episode closure recomputes that binding and rejects an
assessment if a later observation has made it stale. The closure ledger event
also carries the bound observation-set hash.

`snapshot()` now reads lifecycle rows, reward aggregates, and the event chain
from one read-only repeatable-read transaction. The PostgreSQL 16 integration
suite verifies that every component and event-chain check uses the same client
and database view.

## Reviewable six-permutation demo

The three-agency browser demo now:

- reconciles all six possible source-order permutations and requires one
  proposal hash across them;
- binds a submitted disposition to both the current canonical proposal hash and
  current entity-resolution decision hash;
- validates every supplied canonical or entity selection against the current
  proposal, including return-for-correction dispositions;
- exposes the complete reconciliation proposal, entity input and decision,
  versioned access policy, access requests and receipts, and recorded
  selections for inspection;
- labels recorded activation and entity-link state explicitly, while preserving
  the in-memory, non-activating review boundary;
- improves keyboard focus, focus contrast, source-change announcements, and
  narrow-screen layout; and
- keeps static files on a fixed allowlist with security headers, rejects
  non-loopback Host values, rejects a mismatched browser Origin on review POSTs,
  and returns route-specific `405` responses and `Allow` headers.

The app still does not authenticate a reviewer, persist a durable disposition,
activate a canonical revision, merge an entity, issue an access token, or
enforce disclosure.

Run it from a contributor checkout:

```bash
npm run build --workspace @t2kai/core
npm test --prefix examples/integration-hub-demo
npm run smoke --prefix examples/integration-hub-demo
npm start --prefix examples/integration-hub-demo
```

Open <http://127.0.0.1:4173>.

## Signed mainline release gate

The core and `create-t2k` publishers now require GitHub-verified annotated
release tags. Each workflow binds the GitHub tag-object and peeled commit SHAs
to the local tag and checkout, fetches `origin/main`, and requires the release
commit to be on that mainline history before OIDC publication. Lightweight,
unsigned, moved, checkout-mismatched, and off-main tags fail closed.

Before creating the signed tags, maintainers must run the complete clean-checkout
suite and PostgreSQL 16 integration path described in
[`docs/RELEASING.md`](../RELEASING.md). Registry installation and provenance
verification remain separate post-publication gates.

## Generate or install 0.4.2

```bash
npm install @t2kai/core@0.4.2
npx create-t2k@0.4.2 my-decision-loop
npx create-t2k@0.4.2 my-integration-hub --profile integration-hub
```

Generated projects depend on `@t2kai/core@^0.4.2`.

## Package versions

- `@t2kai/core@0.4.2`
- `create-t2k@0.4.2`
- `@t2kai/mcp@0.3.0` (unchanged)

All packages require Node.js 20.10 or newer. T2K remains Apache-2.0. Managed
connectors, production identity, durable human review, IAM enforcement, records
management, and hosted operations remain outside the open reference runtime.

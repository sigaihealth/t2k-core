# T2K 0.4.1: Hardened Inputs, Complete Evidence, Runnable Review

T2K 0.4.1 is a patch release focused on failing closed at integration
boundaries, making retry behavior safe, and proving the developer path through
a realistic three-source demo application.

## What changed

### Runtime hardening

- Purpose-access requests with blank or malformed required identity, role,
  purpose, subject, category, jurisdiction, time, or source evidence now receive
  a deterministic `invalid_request` deny. Malformed policy and request shapes no
  longer escape as native type errors.
- Entity resolution no longer silently replaces an invalid supplied threshold
  with a permissive default. Invalid thresholds, input collections, candidates,
  or rules prohibit automatic matching and remain bound into the decision
  evidence.
- Mapping rejects unknown source-authentication enum values, records the
  normalized assertion as `unknown`, and routes the result to review rather
  than allowing malformed evidence to reconcile. Calendar-impossible
  `iso_date` values and malformed nested execution inputs also fail closed.
- Postgres execution and observation timestamps now require a real calendar
  timestamp with `Z` or a numeric offset. Exact execution-receipt retries return
  the original receipt, changed key reuse conflicts, and exact observation
  retries return the original observation without adding another ledger event.

### Complete generated evidence

The `integration-hub` scaffolder now hashes a complete packet containing:

- the exact loaded `@t2kai/core` package version;
- every complete canonical record and its complete mapping receipt;
- the complete versioned authority policy;
- the complete forward and reverse reconciliation proposals, candidates,
  provenance, and issues; and
- an explicitly scoped input-order comparison.

Generated JSON errors identify the failing filename. Generated PostgreSQL binds
to `127.0.0.1:55432`; its `t2k` username and password are disposable local-only
quickstart credentials.

### Runnable three-agency demo

The new `examples/integration-hub-demo` browser app executes the real core APIs
against three synthetic agency schemas. It preserves mapping receipts and
conflicts, checks three input orders, proposes an ambiguous reversible entity
link, evaluates an explicit allow and a default deny, and lets a reviewer write
only an in-memory disposition. It does not authenticate a human, activate a
canonical revision, merge an entity, or enforce access.

Run and verify it from a contributor checkout:

```bash
npm ci
npm run build --workspace @t2kai/core
npm test --prefix examples/integration-hub-demo
npm run smoke --prefix examples/integration-hub-demo
npm start --prefix examples/integration-hub-demo
```

Open <http://127.0.0.1:4173>. The isolated smoke packs core, installs the tarball
into a fresh temporary consumer, and runs the complete model from package
output.

## Generate the hardened profile

```bash
npx create-t2k@0.4.1 my-integration-hub --profile integration-hub
cd my-integration-hub
npm start
```

Do not edit a mapped source envelope in place. Copy it to a new filename and
assign a new locator, record key, payload record ID, and event/observation
times. Preserve the earlier evidence and the shared party key. Bump
`policyVersion` after changing authority priorities; bump `mappingVersion` and
`ontologyVersion` after changing a mapping; and bump `ontologyVersion` for any
other ontology contract change.

The fixed timestamps, policy windows, and retention metadata in the tutorial
are replay fixtures. They are not current approval or retention enforcement.
The mapper preserves retention metadata but does not delete records.

## MCP boundary

Pin the compatible adapter:

```bash
npx -y @t2kai/mcp@0.3.0 --help
```

The mapping result can feed canonical reconciliation. Entity-link and
purpose-access evaluation are independent read-only computations, not later
automatic stages. Setting `T2K_DATABASE_URL` adds separate lifecycle tools; it
does not persist, approve, or activate integration outputs. Persisted proposals,
authenticated human dispositions, canonical activation, entity merging, and IAM
enforcement remain trusted-application responsibilities outside MCP.

## Hash interpretation

`sourceValueHash` binds the raw source value before normalization and value
mapping. A reconciliation candidate's `valueHash` binds the transformed
canonical value. Their difference is expected and preserves the distinction
between evidence received and value compared.

## Maintainer verification

The release gate is:

```bash
npm run check
T2K_TEST_DATABASE_URL=postgresql:///postgres npm run check:postgres
npm test --prefix examples/integration-hub-demo
npm run smoke --prefix examples/integration-hub-demo
npm run pack:core
npm run pack:mcp
npm run pack:create-t2k
```

The Postgres command requires a reachable disposable test database. Package
publication, tag verification, live tutorial deployment, and registry
installation are separate release gates and must each be verified after this
local suite.

## Package versions

- `@t2kai/core@0.4.1`
- `create-t2k@0.4.1`
- `@t2kai/mcp@0.3.0`

All packages require Node.js 20.10 or newer. T2K remains Apache-2.0; managed
connectors, enterprise identity, hosted operations, customer data, records
management, and compliance services are outside the open reference runtime.

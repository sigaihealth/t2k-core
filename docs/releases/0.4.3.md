# T2K 0.4.3: Evidence-Bound Inputs and Legacy Reward Quarantine

T2K 0.4.3 is a security and compatibility patch for the public core runtime,
the generated projects, and the local integration-hub demo.

## Upgrade

```bash
npm install @t2kai/core@0.4.3
npx create-t2k@0.4.3 my-integration-hub --profile integration-hub
```

Generated projects pin `@t2kai/core@0.4.3` exactly so a scaffold run and its
installed runtime remain one reviewed release unit.

## Public object boundary

Purpose-access, source-mapping, reconciliation, and entity-resolution calls now
snapshot recursively enumerable own JSON data once. Validation, decisions, and
semantic hashes all use that same snapshot. Inherited properties are ignored;
own getters are not invoked. Accessors, cycles, sparse arrays, non-finite
numbers, and non-JSON values fail closed.

Pass parsed JSON or ordinary data records. Behavior-bearing class instances may
be accepted only for enumerable own data; prototype behavior is never evidence.

## PostgreSQL schema-v2 repair

Fresh and upgraded databases now use the same nullable
`reward_assessments.observation_set_hash` column. The nullable layout is
intentional: it preserves temporary 0.4.1 rollback compatibility because that
runtime omits the column when it inserts an assessment.

This is schema, migration, and insert compatibility—not full behavioral safety
on the older runtime. Treat 0.4.1 as an emergency write-limited rollback. It
does not enforce the quarantine below, so while it is active do not close
episodes, create or evaluate learning candidates, promote or deploy policies,
or consume reward aggregates. Restore 0.4.3 before those operations.
Do not mix or roll back to 0.4.2 during this transition. Although its migration
leaves an existing nullable column in place, that runtime does not enforce the
quarantine and may consume unbound evidence in learning, evaluation, promotion,
or aggregate paths. Use only the documented write-limited 0.4.1 emergency path
or restore 0.4.3.

A null hash means the assessment is legacy and unbound. T2K does not guess or
backfill a historical observation set because 0.4.1 allowed observations to be
recorded after assessment. The latest unbound assessment is excluded from:

- episode closure;
- candidate training;
- holdout replay;
- candidate promotion or staged promotion deployment; and
- snapshot reward aggregates.

After returning to 0.4.3, recompute an open episode's reward on the current
observation set before closure. A closed unbound episode cannot be reassessed;
it remains quarantined and must be replayed as a new episode if its evidence is
needed.

## Timestamp and local-demo hardening

Reward observations require calendar-valid ISO timestamps with an explicit UTC
offset. Equivalent instants now order identically in every host timezone. The
local demo also validates an exact JSON media type, rejects Host userinfo, and
requires a syntactically exact same-origin Origin header for review mutations.

Publication workflows pin third-party actions to immutable commits, and the
published `create-t2k` artifact includes the full Apache-2.0 license.

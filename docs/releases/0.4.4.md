# T2K 0.4.4: Accepted Deployments and Evidence-Bound Evaluation

T2K 0.4.4 is a trust-hardening patch for the public Core runtime, MCP adapter,
and generated-project release unit. It does not change the database schema.

## Package versions

```bash
npm install @t2kai/core@0.4.4
npx -y @t2kai/mcp@0.3.1 --help
npx create-t2k@0.4.4 my-integration-hub --profile integration-hub
```

- `@t2kai/core@0.4.4`
- `@t2kai/mcp@0.3.1`, requiring `@t2kai/core@^0.4.4`
- `create-t2k@0.4.4`, with both templates pinning Core 0.4.4 exactly

The `create-t2k` CLI behavior and profile names are unchanged. Its patch bump
keeps generated projects on the same reviewed Core release instead of silently
scaffolding the older 0.4.3 runtime.

## Trust hardening

- Use compiler `mode: "deployment"` for release-bound resolutions. Only
  `accepted` packs are eligible; a newer draft cannot shadow an accepted pack.
- Replay now rejects blank, duplicate, and conflicting episode IDs before
  computing sample size, coverage, or confidence.
- Reward evaluation rejects conflicting latest-timestamp observations and
  mixed-type numeric aggregations. `evidenceMode: "strict"` additionally
  requires the source, human-review, comparison, experiment, previous-state,
  or control references declared by the reward contract.
- New optional mapping selectors bind a mapping to `sourceSystem`, exact or
  prefix `sourceLocatorMatch`, and `acceptedAuthorityRefs`.
  `expectedMappingHash` pins the independently selected mapping revision;
  `canonicalSourceMappingHash` computes that public canonical digest.
- Trim-equivalent authority references are rejected rather than normalized
  into duplicates, and invalid runtime compiler modes fail closed as
  deployment.
- MCP rejects arguments beyond its published nesting, node, collection,
  property-key, per-string, aggregate-text, and batch limits before semantic
  evaluation.
- MCP releases now require the same GitHub-verified annotated tag, checked-out
  commit, and protected-main ancestry evidence as Core releases.

The conformance kit includes thirteen portable JSON input/outcome vectors for
these behaviors.

The three-source integration demo now declares ontology 1.0.1 and advances all
three mapping versions for the selector-bearing mapping revisions.

## Compatibility and migration

Existing callers remain on `authoring` compilation when `mode` is omitted.
That default retains the previous authoring resolution hash. Existing reward
callers remain on `evidenceMode: "legacy"`; migrate new or remediated workflows
to strict evidence after adding their method-specific references.

Source selectors are optional. Mappings that omit them preserve their existing
routing behavior and semantic hash shape. Adding selectors intentionally
changes the mapping hash, so bump `mappingVersion` and the containing
`ontologyVersion`, review the new hash, and pin it at execution.

`acceptedAuthorityRefs` is a normalized set: surrounding whitespace and order
do not change its canonical mapping hash, while values that collide after
trimming are invalid.

The stronger duplicate replay, tied-latest reward, and mixed-type aggregation
checks fail closed for ambiguous evidence even in compatibility modes. Correct
or de-duplicate that evidence rather than suppressing the checks.

No PostgreSQL migration is required. Rolling application code back to Core
0.4.3 and MCP 0.3.0 does not require a schema rollback, but it removes the new
deployment, evidence-binding, input-limit, and MCP release controls.

The expected release tag names are `core-v0.4.4`, `mcp-v0.3.1`, and
`create-t2k-v0.4.4`. Preparing this release does not itself create those tags
or publish any package.
